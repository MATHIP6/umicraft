# ADR-0050 — P11: audio engine on cpal and lewton, own mixer

Status: accepted (2026-11-05)

## Context

P11 needs a sound engine: the `sounds.json` index, Ogg Vorbis decoding, 3D
positioned playback with the vanilla distance rule, category volumes and
source limits. Spec §5.3 and `docs/threading.md` forbid any block on the game
or render thread, and spec §3.7 requires every dependency licence to pass
`cargo deny` with the current allow list (MIT, Apache-2.0, BSD, ISC, Zlib,
Unicode-3.0).

## Options checked (current versions, 2026-11-05)

| Option | Licence | Verdict |
|---|---|---|
| `kira` 0.12.6 (default features) | MIT OR Apache-2.0, but pulls `symphonia` (MPL-2.0) and `triple_buffer` (MPL-2.0) | `cargo deny check licenses` fails. |
| `kira` without default features | its own `triple_buffer` dependency is MPL-2.0 | Still fails; cannot be avoided by features. |
| `cpal` 0.18.2 + `symphonia` | Apache-2.0 + MPL-2.0 | Fails on `symphonia`. |
| `cpal` 0.18.2 + `lewton` 0.10.2 + own mixer | Apache-2.0 + MIT OR Apache-2.0 | `cargo deny check licenses` passes unchanged. |
| `rodio` | MIT OR Apache-2.0, but decodes with symphonia by default | Same MPL problem unless configured with lewton; adds a layer we would not use. |

MPL-2.0 is a file-level copyleft licence and is generally usable from
MIT/Apache code as an unmodified dependency, but widening the allow list is a
project policy decision (spec §3.7) that belongs to the owner. Nothing in P11
needs it, so the policy is left alone.

## Decision

- **Output: `cpal`** (low level, Apache-2.0). The device callback runs on cpal's
  realtime thread.
- **Decoding: `lewton`**, a pure-Rust Vorbis decoder, the counterpart of the
  JOrbis codec vanilla registers in `SoundManager`. `decode_ogg` is a pure
  function on bytes.
- **Own mixer** (`backend::mixer`): about 150 lines that sum voices with
  linear resampling (for the source rate and the pitch), a linear stereo pan
  and a clamp. It is pure code, unit-tested without a device, and allocation
  free while rendering. Vanilla needs nothing more than that: no effects, no
  reverb, a fixed 28 + 4 source budget.
- **Distance and pan are computed by us**, not by a library spatial engine:
  `attenuation.rs` is the exact vanilla rule (16 x max(volume, 1) blocks,
  linear), and the pan comes from the listener heading.
- **One audio thread** owns the engine; the game holds an `AudioHandle`, a
  bounded `sync_channel(256)` sender whose `play` is a `try_send` that drops
  and counts when the queue is full. See `docs/threading.md` (Audio boundary).
- **Trait seam**: `AudioBackend` (`play`, `reap`) with `CpalBackend` and a
  recording `NullBackend`, so the engine, the limits and the delayed sounds are
  tested without a sound card, and a machine with no device still runs (the
  thread falls back to the null backend).
- **Streaming decode: see ADR-0052.** (Was: no streaming decode yet.) Entries with `stream: true` (music, records) are
  decoded whole and counted against the 4 streaming sources. Whole-file decode
  is fine for the first lots; a streaming path can replace it behind the same
  trait if the memory of music tracks matters (the cache is bounded at 64 MiB
  and does not keep a file larger than that).

## Consequences

- Playing sounds are not updated when a category volume changes (they are
  short); new sounds use the new volume. Vanilla also rescales running
  channels; revisit if long records need it.
- `cpal` needs the ALSA development files on Linux (`libasound2-dev`) at build
  time.
- The device must offer `f32` samples (the default configuration of the common
  hosts); otherwise `CpalBackend::new` fails and the thread runs muted.
