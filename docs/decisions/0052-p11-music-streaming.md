# ADR-0052 — P11-G: music runs off the audio thread's critical path

Status: accepted (2026-11-05)

## Context

A music track is a 3-4 minute Ogg Vorbis file (several MB, 10-20 million PCM
samples decoded). ADR-0050 decodes every sound whole on the audio thread, which
is right for 0.1-2 s effects but would stall footsteps and clicks for tens of
milliseconds (release) to seconds (debug) when a track starts. The music
ticker also needs to know whether its track is still audible, and the world
needs a way to stop it, without any blocking call from the game or render
thread (spec §5.3).

## Decision

- **Decoding of `stream: true` entries happens on a worker thread**
  (`umicraft_audio::stream::StreamDecoder`, started on the first stream). The
  audio thread only reads the file bytes (a plain read, no decode), sends them
  over an `mpsc` channel and polls the result with `try_recv` on its 20 Hz tick.
  The voice starts on the first tick after the decode; a 300 ms start delay of a
  background track is inaudible. Streamed PCM is not put in the cache (a track
  would evict the effects).
- **Whether music is in flight is two atomic counters** (`MusicActivity`):
  `AudioHandle::play_music` counts a request *before* queueing it; the audio
  thread counts it finished when the voice ends, the decode fails, the request is
  silent or unknown, or a stop cancelled it. `music_playing()` is
  `requested != finished`. A plain flag would race with the audio thread's tick
  (a request still in the queue would read as "ended" and the ticker would start
  a second track).
- **`AudioMessage::StopMusic`** stops every streaming voice (`AudioBackend::
  stop_streaming`; the cpal callback does it from an atomic request) and bumps a
  generation, so a track still decoding is discarded when it arrives.
- **The client paces the ticker** (`audio_bridge::music`) with its own 20 Hz
  clock on the render thread (at most 4 ticks per call after a stall). The
  dimension and game mode travel in `Frame` (two bytes) so the situation is
  `Menu` without a world, else `Nether`/`End` by dimension, `Creative` for a
  creative player, `Game`.

## Consequences

- The file read of a track (a few MB from the asset store, SHA-1 checked) still
  happens on the audio thread; measured nothing yet, expected a few ms.
- A streaming voice that is not music (jukebox records, not generated by the
  game yet) also decrements `MusicActivity` when it ends; the counter saturates,
  so it cannot go negative, but a record ending during a track would end the
  track's "playing" state early. Revisit when records are played.
- A stopped track is reported by the next `reap`, up to 50 ms later; the ticker
  ignores `track_playing` after its own stop, so this is invisible.
